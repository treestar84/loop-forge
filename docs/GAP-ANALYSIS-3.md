# 갭 분석 3차 — 게임 계열 전수 탐색 (v1.2 → v1.3)

> 방법: 특정 게임이 아니라 **게임 메커니즘의 계열(family)** 단위로 탐색 공간을 펼쳐,
> 각 계열이 4계층의 어디를 압박하는지 가지별로 검증(ToT)한 뒤 수렴시켰다.
> 1·2차(GAP-ANALYSIS.md, GAP-ANALYSIS-2.md)에서 닫은 갭은 "수용 확인"으로만 기록한다.
> 목적: 실전 게임 투입 전에 4계층의 설계·구조·대응성을 계열 수준에서 단단하게 만드는 것.

---

## 계열별 탐색

### F1. 동시 행동 게임 (가위바위보류 · Goofspiel · 7 Wonders 드래프트)
- 계약은 순차(AEC) 전용이다. **은닉-순차 모델**(순서를 정해 진행하되 앞선 선택을 관찰
  에서 숨김)이 정보 이론적으로 등가이며, 그 은닉은 C3 probe로 검증 가능 — 2차 G5로
  성문화됨. ✅ 수용 확인.
- ⚠️ 잔여 한계: **후행자의 합법수가 선행자의 선택에 의존하면** 등가가 깨진다(동시
  게임에서는 의존 불가). 어댑터가 합법수를 "동시 시점 기준"으로 생성해야 한다는 조건을
  가이드에 추가. → [Y-가이드]

### F2. 협상·거래 게임 (카탄 · 모노폴리 딜)
- 오퍼/카운터오퍼는 결정 지점으로 모델링 가능 — 계약 수용. 단 자원 묶음 오퍼는 액션
  공간이 조합 폭발한다: `encodeChoice` 안정성과 합법수 열거 비용(C4)이 압박 지점.
  → 오퍼 공간을 이산화(템플릿 오퍼)하는 표준 패턴을 가이드에. → [Y-가이드]
- 구속력 없는 자유 대화(음성 협상)는 범위 밖 — 적용 범위 선언에 명시. → [Y6]

### F3. 다인 자유전의 킹메이킹·생태계 (카탄 · Root · 다인 카드게임 전반)
- 후보 1 + 동일 기준선 N-1 구성은 **하나의 생태계 표본**일 뿐이다. 진 플레이어가
  승자를 결정하는 킹메이킹 환경에서는 상대 구성이 바뀌면 결론이 뒤집힐 수 있다
  (선행 하네스의 ecology veto 교훈).
- 현 구조에서 벤치마크 앵커 사다리가 다상대 측정을 부분 제공. **필드 믹스 평가**
  (혼합 상대 풀 웨이브)는 로드맵으로 명시하되, INTERPRETATION에 "FFA 채택은 단일
  생태계 결론"이라는 해석 경고를 지금 추가. → [Y-해석 + 로드맵]

### F4. 숨은 진영·사회적 추리 (아발론 · 마피아 · Coup)
- ⚠️ **`spec.teams`는 고정·공개 팀 전용이다.** 아발론의 진영은 은닉이고 종국에
  드러난다 — 정적 팀 선언과 페어드 통계의 팀 풀링이 어긋난다. 처치: 숨은 진영 게임은
  `spec.teams`를 **선언하지 말고** `Outcome.winners`(승리 진영 전원)로 승률을 계산하게
  한다 — winFraction 경로는 이미 winners 기반이라 동작한다. scoreDelta는 진영 풀링이
  안 되므로 "승/패 전용 게임"(F10)으로 취급해 minScoreDiff=0 기준을 쓴다. → [Y-가이드]
- 역할 배정 무작위는 시드→상태 경로로 수용(좌석 미러링이 역할도 순회). 발언/주장은
  구조화된 선택지(클레임 템플릿)로 이산화 — 가이드. ✅/[Y-가이드]

### F5. 비대칭 진영·로드아웃 (Root · 하스스톤 덱 · Cosmic Encounter)
- 2차 G3(덱=설정·좌석 결합·미러 기본)를 **진영(faction) 일반형으로 승격**: "비대칭
  요소는 좌석에 결합하라, 그러면 미러링이 비대칭도 상쇄한다. 기본은 미러 설정,
  비대칭 자체의 평가는 설정별 어댑터로." → [Y-가이드 일반화]

### F6. 중결정 무작위·재량 배팅 (백개먼: 주사위 + 더블링 큐브)
- 결정→주사위→결정 흐름은 상태 내 RNG 패턴(1차 B1)으로, 더블링 큐브는 결정 지점 +
  composite score 배율로 수용. ✅ 수용 확인 (분석 기록만).

### F7. 은닉 "행동" 게임 (스코틀랜드 야드류 — 수가 자체가 숨겨짐)
- 상태 은닉과 동일하게 관찰 빌더가 책임지고 C3 probe(미스터 X 위치 변조)로 검증 가능.
  리플레이 fixture에 전체 수가 담기는 것은 parity 용도이므로 문제 없음. ✅ 수용 확인.

### F8. 덱빌더 (도미니언)
- 게임 중 셔플=상태 RNG(1차 B1), 대량 카드=콘텐츠 커버리지(2차 X2), **킹덤 무작위
  선택은 시드-자연 다양성**이라 오히려 유리. ✅ 수용 확인 — 실전 온보딩 후보군에 추가
  추천(스플랜더 다음 난이도).

### F9. 기억 의존 게임 (카드 카운팅이 실력인 게임 전반)
- ⚠️ **봇 상태 규칙이 미성문화.** `GameBot`은 객체라 게임 내 decide() 호출 간 내부
  상태(카운팅 메모리)를 가질 수 있고 이는 의도된 설계다. 그러나 (a) **게임 간
  캐리오버 금지**(매 게임 fresh 인스턴스 — 러너가 보장하지만 규칙으로 명문화),
  (b) 관찰에 **공개 히스토리를 포함**해 봇 메모리 없이도 정보 집합이 완전하도록
  권장(봇 구현 난이도와 재현 디버깅 모두에 유리) — 을 가이드에 성문화. → [Y5]

### F10. 승/패 전용 게임 (점수 마진이 없는 게임: 오목·아발론·레이스 게임)
- ⚠️ scoreDiff가 정보를 갖지 않는다(승리=1/패배=0의 재표현). `minScoreDiff` 기본값
  (0.3/5 등)을 그대로 쓰면 **모든 후보가 near-miss로 오판**될 수 있다. 처치:
  가이드·해석에 "승/패 전용 게임은 criteria.minScoreDiff=0으로 설정하고 scoreDiff
  열을 무시하라" 성문화 + near-miss 정의가 이 경우 무의미함을 명시. → [Y2]

### F11. 초장기 게임 (트와일라잇 임페리움류 — 수백 결정·저처리량)
- C4 blocker는 **정직한 판정**이다("이 게임은 수십만 판 루프가 물리적으로 불가").
  대응 전략(축소 설정 어댑터, 서브게임 단위 평가, 결정 수 상한 변형)을 가이드에.
  → [Y8]

### F12. 범위 밖 계열 (명시적 제외 선언)
- **실시간·신체 게임**(스피드류·덱스터리티), **레거시/캠페인**(게임 간 영속 상태),
  **1인/협력**(2차 G2), **자유 음성 협상**. 계약이 암묵적으로 배제하지만 성문화가
  없어 온보딩 시도 후 실패하는 낭비 가능. → 적용 범위 섹션 신설. → [Y6]

## 계층 관통 점검 — 의존성 분리 (사용자 상시 요구사항)

실제 import 그래프를 감사한 결과:

```
contract  ← kernel ← loop ← onboarding
                   ↖ artifacts (loop의 타입·kernel 사용)
reference ← (contract, kernel/rng만)     demo → 전 계층 (앱 경계)
```

- ✅ 게임 지식이 contract 위로 새지 않음(선행 하네스에서 mistake-detector가 오염됐던
  실패의 재발 없음). kernel은 contract 타입만 안다.
- ⚠️ **[Y1-a] DESIGN.md의 계층 다이어그램이 개념 순서(②가 ③ 아래)로 그려져 있어 실제
  의존 방향(onboarding→loop→kernel→contract)과 다르다** — 문서 정정 필요. 다이어그램과
  코드가 어긋나면 다음 기여자가 잘못된 방향으로 import를 추가한다.
- ⚠️ **[Y1-b] 의존성 규칙이 문서로만 존재하고 기계적으로 강제되지 않는다.** 지금까지는
  에이전트 지시로 지켰지만, 성장하면서 한 번의 실수로 무너진다. 처치: **의존성 린트
  테스트** — 허용 edge 목록을 선언하고 위반 import를 실패시키는 jest 테스트. 동시에
  **결정론 린트 테스트** — `Date.now()`/`Math.random()`이 허용 파일(demo 등 앱 경계)
  밖에서 등장하면 실패. 둘 다 CI에서 영구 강제.
