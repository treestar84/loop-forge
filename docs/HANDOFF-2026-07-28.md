## 4. 오목 C열(챗봇 AI 대비 맞대결) — 5개 카드 전부 실패, 완전히 소진됨

사용자가 "루프포지 전략도 오퍼스급인데 왜 약한가"를 문제 제기해 정밀 진단한 결과:

1. 예산 2배(`mcts2-s512-hr`) — 0%
2. 롤아웃 정책 교체/챔피언 흉내(`mcts2-s256-cr`/`s512-cr`) — 0%
3. 전술 프리체크(즉승/즉방어, `tacticalDepth`) — 0%
4. **다방향 위협(포크) 인식을 게임 지식으로 정식 구현**(`forkAwareness`) — 탐색 없는
   순정 휴리스틱은 **9.0%로 최초 돌파**, 그러나 MCTS 롤아웃으로 감싸면 다시 0.0%
5. **탐색을 우회하는 루트 오버라이드**(`rootOverride` 훅, 게임 중립 인프라) — 여전히
   0.0%(계측으로 41.1% 실제 발동 확인 — 배선 버그 아님)

**결론(정직한 최종 상태)**: 오목은 현재 구조(256-sim 얕은 MCTS)로는 챗봇 AI를 못
이긴다. `rootOverride` 훅과 `forkAwareness` 플래그는 재사용 가치가 있어 그대로
남겨뒀다. 다음 카드가 있다면 예산을 훨씬 크게 늘리거나(비용 문제 별도 검토),
포크 정의를 연속/이중 위협 체인까지 확장하거나, 순수 탐색 심화 접근 자체의
재검토가 필요하다 — **이건 다음 세션이 "왜 안 되지"를 처음부터 다시 조사하지
않게 하려고 남기는 기록이다.**

## 5. 알아둘 실측 통찰 (재발견 방지용)

- **`identityCenter=1/N` 가정은 승리조건이 대칭일 때만 성립한다.** 카탄(대칭,
  단일승자)은 자기대국이 정확히 1/4(CI 폭 0)로 수렴하고, 아발론(비대칭, OR/AND
  혼합 승리조건)은 20.5%로 벗어난다 — 둘 다 버그가 아니라 각 게임의 수학적 구조다.
- **registry가 동적 플래그(`withStrategyFlags`)로 승격되면 구 벤치마크 러너가
  깨진다** — 원본(미확장) 어댑터에 `composeBot`을 호출하면 "unknown strategy
  flag" 에러. 하스스톤 v2, 스플랜더 v3 둘 다 이 패턴이었다. 새 버전용 벤치마크
  파일을 만들 때는 항상 `withStrategyFlags`로 확장한 어댑터를 써라.
- **롤아웃 정책으로 쓰면 오히려 나빠지는 전략이 있다** — "단독 평가에서 강한
  전략"이 "롤아웃 시뮬레이션 정책"으로는 나쁠 수 있다(장기의
  captureHighestValue+preferCheck 조합, 도미니언의 챔피언 롤아웃 1차 시도 둘 다
  근거 있는 실패였다). 이유(안전 무시·자멸 패턴 유도)를 FIX-BACKLOG에 기록해뒀다.
- **무거운 연산은 항상 동시 1개.** 2026-07-23 밤 병렬 에이전트 3개의 동시 실행으로
  메모리 고갈·세션 중단 사고가 있었다(GAP-ANALYSIS-8 §4). 이후 전 라운드에서
  `ps aux` 확인 → `nice -n 10` → 힙 오버라이드 금지 규칙을 지켰고 재발 없음.
