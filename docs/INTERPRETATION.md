# 벤치마크 해석 가이드 — 숫자를 어떻게 읽는가

> Loop Forge가 내는 모든 리포트의 지표 정의와 해석 규칙. 반복 사용 시 항상 같은
> 방식으로 읽기 위한 성문화된 기준이다. 리포트 상단의 `comparabilityKey`가 다른
> 두 리포트의 수치는 **직접 비교하지 않는다** — 이것이 제1규칙이다.

## 1. 비교 가능성 규칙 (제1규칙)

승률·점수차는 절대값이 아니라 **특정 문맥 안의 상대값**이다. 문맥 = 다음 4요소:

| 요소 | 의미 |
|---|---|
| adapterDigest | 게임 룰 구현의 identity (룰이 바뀌면 과거 수치 무효) |
| baselineVersion | 후보의 베이스가 된 기준선 버전 |
| opponentId | 상대 봇 identity |
| seedBankIds | 사용한 시드 뱅크 |

이 4요소를 canonical digest로 묶은 것이 `comparabilityKey`다. 키가 같을 때만
"A 플래그가 B 플래그보다 낫다"를 말할 수 있다. 키가 다르면 **벤치마크 앵커 사다리**
(§5)로만 진행도를 비교한다.

## 2. 지표 정의

| 지표 | 정의 | 주의 |
|---|---|---|
| winRate (블록) | 한 게임 시드를 좌석 순열 전체로 돌린 평균 승리분수. 승=1, 비팀 공동승=0.5, 패=0 | 좌석 편향이 상쇄된 값. 단일 게임 승률이 아니다 |
| pointWinRate | 블록 winRate들의 평균 | 표본 수(블록 수)와 함께 봐야 함 |
| winRate CI | 시드 블록 퍼센타일 부트스트랩 95% 신뢰구간 | **CI 하한이 0.5를 넘는지**가 "효과 있음"의 기준 |
| scoreDiff | candidate(팀) 점수 − 상대(팀) 점수의 블록 평균 | 게임마다 스케일이 다르다 — 게임 간 비교 금지 |
| drawRate | winFraction=0.5인 블록 비율 | 높으면(>0.6) SPRT 검정력 저하 — smoke가 한도까지 갈 수 있음 |
| bias | 항등 캘리브레이션의 좌석별 승률 최대−최소 | 이 값이 곧 이 게임의 좌석 편향 크기. 페어드 설계가 상쇄하지만, 클수록 표본이 더 필요 |
| 항등 기대값 | 자유전 1/인원수, 팀전 1/팀수 | **0.5는 2인 게임의 우연**이다. 4인 자유전 항등은 0.25가 정상 — 3~4인 게임에서 0.5를 기대하지 마라 |
| noise floor | 항등 대국(같은 봇 vs 같은 봇) winRate CI의 폭 | **효과 크기가 이 폭 안이면 판정 불가** — 표본을 늘려라. recommendBlockCount가 필요 블록 수를 계산해준다 |
| signalCollapseRate | winFraction이 정확히 0.5인 블록 비율 | 높으면(0.8↑) 미러링이 신호까지 상쇄 중 — 선공 우위 지배 게임의 증상. CI가 [0.5,0.5]로 좁아도 **정밀한 게 아니라 신호가 없는 것**이다. 오프닝 다양성/불균형 오프닝으로 해소 |

## 3. 판정(verdict) 읽는 법

| verdict | 의미 | 해석 |
|---|---|---|
| adopted | screen→smoke→prune→**holdout**(미사용 예약 시드) 전부 통과 | 기준선 반영 자격. 유일하게 "효과 입증"을 뜻하는 판정 |
| screened | smoke까지만 통과 | **채택 아님**. smoke는 SPRT 선별일 뿐 — 40~수십 블록의 표준오차는 수 %p에 달한다 |
| near-miss | 승률은 기준을 넘었지만 점수차 미달 | 방향은 맞을 수 있음. 조건을 좁혀 재설계 후보 |
| failed | 게이트 탈락 또는 defect | defect 사유가 있으면 전략이 아니라 **어댑터/봇 결함** — 통계로 읽지 마라 |
| screened-out | screen(0판)에서 행동 무변화 판정 | 전략이 아무 결정도 바꾸지 않았다(no-op). 구현 오류이거나 발동 조건 미도달 |

핵심 규칙 (선행 하네스의 ±7.9%p 사고에서 성문화):
- **smoke 수치로 아무것도 결론내지 않는다.** smoke는 예산 절약용 선별이다.
- **holdout 수치만 채택 근거다.** holdout 시드는 학습에 쓰인 적 없는 예약 뱅크다.
- CI 하한 > 0.5 (승률) 그리고 CI 하한 > 0 (점수차)를 함께 확인하라. 점추정만 보지 마라.

## 3.5 게임 계열별 해석 경고

- **승/패 전용 게임(마진 없음)**: scoreDiff·near-miss는 무의미하다. `minScoreDiff=0`
  설정을 확인하고 승률 CI만 읽어라. 기본 기준을 쓴 리포트라면 near-miss 판정을
  신뢰하지 마라 (GAP-ANALYSIS-3 Y2).
- **FFA(3인 이상 자유전) 채택은 단일 생태계 결론이다**: "후보 1 + 동일 기준선 N-1"
  구성에서의 승률이며, 킹메이킹이 있는 게임에서는 상대 구성이 바뀌면 뒤집힐 수 있다.
  채택 후 앵커 사다리의 여러 상대 수치를 함께 확인하라. 혼합 상대 풀 웨이브는 로드맵
  (GAP-ANALYSIS-3 Y7).
- **signalCollapseRate가 높은 리포트**: §2 표의 규칙대로 — CI가 좁아도 신호가 없는
  것이다. 오프닝 다양성부터 해결하고 다시 측정하라.

## 4. SPRT 읽는 법

- `accept`: 승률이 p1(대립가설) 쪽이라는 증거가 임계 도달 — prune으로 진행.
- `reject`: p0(효과 없음) 쪽 증거 임계 도달 — 조기 탈락. **"약간 나쁨"이 아니라
  "p1만큼 좋지는 않음"이다.**
- `continue`(한도 소진): 증거 불충분. 점추정>p0이면 통과 처리되지만 신뢰도는 낮다 —
  prune/holdout이 실질 판정을 맡는다. drawRate가 높은 게임에서 자주 발생(정상).

## 5. 벤치마크 앵커 사다리 — 버전 간 진행도

comparabilityKey가 다른 시점끼리 비교하려면, **동결된 앵커 봇들**(random, heuristic,
과거 기준선 스냅샷)을 상대로 한 사다리 점수를 쓴다. 앵커는 절대 갱신하지 않는다
(선행 하네스의 "V49 스냅샷 불변" 규칙). 새 기준선이 나올 때마다 사다리를 다시 돌려
`runs/`에 기록하면, "V3 기준선은 V1 대비 앵커전 승률이 얼마나 올랐나"로 진행도를
읽는다. 단, 앵커전 승률 상승이 둔화되는 것은 실력 정체가 아니라 **앵커 대비 포화**일
수 있다 — 상위 앵커(최신 동결 버전)전 수치를 우선 보라.

## 6. 반복 사용 시 표준 절차

1. 새 웨이브 전: `runs/` 최신 리포트에서 남은 문제·금지 패턴을 읽는다 (큰 루프 입력).
2. 시드 뱅크는 원장에서 새로 예약한다. **holdout 뱅크 재사용 금지** — 원장이 막지만,
   같은 뱅크로 여러 웨이브를 돌리는 것도 메타 과적합이다.
3. 웨이브 후: AdoptionLedger에 자동 기록된 채택/실패와 사유를 확인하고,
   adopted가 있으면 BaselineRegistry로 다음 버전을 합성한 뒤 앵커 사다리를 갱신한다.
4. 결과 해석에서 막히면 이 문서 §1~§5로 돌아온다. 이 문서에 없는 해석 규칙이
   필요해졌다면 — 그것이 이 문서에 추가돼야 할 다음 항목이다.
