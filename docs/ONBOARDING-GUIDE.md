# 게임 온보딩 가이드 — G-Profile → G-Score → G-Convert → G-Parity

> 오픈소스 게임 프로젝트를 Loop Forge 위에 올리는 표준 절차. 이 문서의 체크리스트를
> 순서대로 완료하면 적합성 게이트(C0~C8)를 통과할 수 있는 어댑터가 나온다.
> 게임별 함정은 §5(결정론 게임 — 체스류)와 §6(은닉·다인수 게임 — 훌라류) 참고.

## 0. 적용 범위 — 온보딩을 시작하기 전에 확인하라

Loop Forge v1이 다루는 것: **턴제 · 경쟁(2인 이상) · 게임 간 독립** 게임.
아래 계열은 범위 밖이다 — 온보딩을 시도하기 전에 여기서 걸러라 (GAP-ANALYSIS-3 Y6):

| 제외 계열 | 이유 | 상태 |
|---|---|---|
| 실시간·신체(덱스터리티) 게임 | 턴제 AEC 모델과 근본 불일치 | 지원 계획 없음 |
| 1인/협력 게임 | 승률 기반 통계의 전제(경쟁 대국) 부재 — C0가 차단 | 로드맵 |
| 레거시/캠페인 게임 | 게임 간 영속 상태가 "게임 간 독립" 전제 위반 | 로드맵 |
| 자유 대화 협상 | 구조화 불가능한 행동 공간. 단, 이산화된 오퍼(§7)는 지원 | 부분 지원 |

## 1. G-Profile — 게임 파악

`parseGameProfile` 스키마(`src/onboarding/profile.ts`)를 채운다. 소스를 읽으며 다음을
인벤토리화한다:

- [ ] 페이즈 구조와 턴 순서 (누가 언제 어떤 결정을 하는가)
- [ ] 결정 지점 목록 — 봇이 선택을 내리는 모든 순간 (멀리건/플레이/타겟 지정/버리기…)
- [ ] 무작위성의 원천 전부 (초기 셔플, 게임 중 셔플/드로우, 주사위) + 각각 시드 주입
      가능 여부. **하나라도 시드 불가면 G-Convert에서 반드시 해소해야 한다.**
- [ ] 은닉 정보의 경계 — 누가 무엇을 보면 안 되는가
- [ ] 승패·점수 판정 규칙과 **종국 보장 규칙**(무한 게임 방지: 반복/무진행 무승부 등)
- [ ] 기존 AI/NPC 로직의 위치 — 룰 엔진과 얼마나 얽혀 있는가
- [ ] UI/네트워크/애니메이션과 룰의 결합 지점

## 2. G-Convert — headless 쌍둥이 구현 체크리스트

`GameAdapter` 계약(`src/contract/types.ts`)을 충족하는 구현을 만든다.

- [ ] **룰 엔진 분리**: UI 이벤트 핸들러에서 룰을 뜯어내 순수 함수화. 원본 프로젝트를
      고치는 게 아니라, 원본의 룰을 참조 구현 삼아 어댑터 안에 headless로 재구성한다.
- [ ] **결정론**: 모든 무작위는 `createInitialState(seed)`의 `createRng(seed)`에서
      출발. `Date.now()`/`Math.random()` 완전 금지.
- [ ] **게임 중 무작위성은 상태에 RNG를 싣는다**: 초기 셔플 후에도 셔플/드로우가
      있으면(훌라의 버림패 재셔플 등) `rng.fork('mid-game')`를 상태에 보관해 소비.
      직렬화가 필요하면 RNG 대신 "남은 시드 스트림 상태"를 상태에 넣는다.
- [ ] **관찰 빌더**: `getObservation`은 은닉 정보가 절대 새지 않는 유일한 통로.
      의심스러우면 "관찰 JSON 문자열에 상대 카드 id가 등장하지 않는다" 테스트를 먼저 써라.
- [ ] **encodeChoice**: 같은 선택은 항상 같은 문자열. 정렬 불안정성 금지.
- [ ] **invariants**: 게임의 보존 법칙(카드 총수, 말 개수+캡처 수 등)을 선언.
- [ ] **기준선 2종**: random(균등 선택) + heuristic(단순하지만 결정적인 규칙).
      heuristic이 random보다 강할 필요는 없다 — "행동이 유의하게 다르면" 된다.
- [ ] **strategySurface**: 실험할 전략 주입 지점. 초기에는 3~10개의 단순 플래그로 시작.
- [ ] **hiddenInfoProbe** (은닉 정보 게임) 또는 **`spec.perfectInformation: true`**
      (완전정보 게임) — 반드시 둘 중 하나.
- [ ] **replayFixtures**: 가능하면 원본 게임에서 뽑은 리플레이(진짜 parity 증명).
      불가하면 어댑터 self-play로 생성한 고정 fixture(재현성 증명으로 격하되며,
      리포트에 그렇게 표시된다).
- [ ] **어댑터 1개 = 게임 설정 1개**: 인원수·룰 옵션이 가변이면 설정별 어댑터를
      만든다(공통 로직은 공유). 예: `hula-3p`, `hula-4p`.
- [ ] **게임 단위 = 독립 채점 가능한 최소 단위**: 다라운드 매치 게임은 1딜/1라운드를
      1게임으로 잡아 통계 표본을 최대화한다.

## 3. G-Score — 채점과 수정 루프

`scoreAdapter(adapter)` 실행 → 리포트의 blocker/remediation을 따라 수정 → 재채점.
임계(기본 70) 미달이면 웨이브 러너가 실행을 거부한다. 축 정의는 DESIGN.md §4.

## 4. G-Parity — 정합성 증명

원본 게임 리플레이 fixture가 재생·일치하는지 확인(C7). 원본에서 리플레이를 뽑을 수
없는 프로젝트라면, 최소한 원본과 어댑터에 같은 수순을 수동으로 넣어 결과 대조한
기록을 남긴다.

## 5. 결정론 게임(체스류) 특별 규칙

- **오프닝 다양성 필수**: 초기 상태가 고정인 게임은 시드가 할 일이 없어서, 결정론적
  봇 간 대국이 전부 동일해진다 → 통계 전멸. `createInitialState(seed)`가 시드로
  오프닝북 라인(수 수순 몇 개를 미리 적용한 국면)을 선택하게 하라. 체스 엔진 테스트
  (Fishtest/OpenBench)의 표준 관행과 동일. 시드 다양성 검사(C1)가 이를 강제한다.
- **종국 규칙 구현 필수**: 반복 무승부·무진행(50수) 규칙이 없으면 랜덤 플레이아웃이
  종국하지 않아 C2 max-decisions defect가 난다.
- **무승부 지배**: 페어드 블록 winFraction에 0.5로 반영되므로 게이트는 건전하지만,
  SPRT 검정력이 떨어진다 → smoke가 min/max 블록 한도로 오래 걸릴 수 있음을 감안.
  리포트의 무승부율 지표를 확인하라 (해석은 INTERPRETATION.md).

## 5.5 결정론 게임 추가 규칙 (2차 갭 분석 반영)

- **다양성은 봇 결정에 맡기지 말라 (장기의 함정)**: 세팅 선택(마상 배치 등)을 결정
  지점으로 두면 자연 다양성처럼 보이지만, 결정론적 봇은 항상 같은 선택을 하므로 실전
  웨이브에서 다양성이 0이 된다 — 그리고 C1 시드 다양성 검사는 random 봇으로 돌기
  때문에 이 함정을 통과해버린다. 초기 국면 다양성은 반드시 **시드가 강제**하라
  (시드-강제 세팅 또는 오프닝북). 런타임 안전망은 signalCollapseRate 경고다.
- **신호 붕괴 대응 (오목의 교훈)**: 선공 우위가 승패를 지배하는 게임에서는 미러링이
  편향과 함께 전략 신호까지 상쇄해 모든 블록이 0.5가 된다. 리포트의
  signalCollapseRate가 높으면(기본 0.8↑ 경고) 오프닝 다양성을 늘리거나 **불균형
  오프닝**(한쪽이 약간 유리한 국면의 미러 배정)을 도입하라. 체스 엔진 테스트의 표준
  관행이다.
- **세부 규칙은 fixture로**: 금수(오목)·타이브레이커(스플랜더) 같은 세부 규칙의
  정확성은 크래시 검사(C2)가 아니라 리플레이 fixture(C7)로 증명된다.

## 5.7 콘텐츠 무거운 게임(윙스팬·하스스톤류) 특별 규칙

- **콘텐츠 커버리지 선언**: 카드 효과 등 콘텐츠가 많으면 `contentInventory` +
  `exercisedContent`를 구현하라. 미선언 시 C2는 "뽑힌 콘텐츠만" 검사한 것이며 리포트에
  커버리지 미측정으로 표시된다.
- **증분 온보딩 전략**: 전체 콘텐츠를 한 번에 구현하지 말라. 기본 부분집합으로 어댑터
  설정을 만들어(`wingspan-core`) G-Score 통과 → 루프 가동 → 콘텐츠를 배치로 확장하며
  커버리지를 늘린다. 룰 버그와 콘텐츠 버그를 분리하는 가장 싼 경로다.
- **덱/로드아웃은 좌석에 결합하라 (하스스톤)**: 덱을 좌석에 묶으면 좌석 미러링이
  매치업도 함께 미러링해 상성이 상쇄된다. 기본 권장은 **미러 매치**(양쪽 같은 덱)로
  실력만 측정하고, 상성 평가는 설정별 어댑터로 분리한다. 덱 구성 자체의 탐색은 로드맵.
- **동시 결정(멀리건 등)은 은닉-순차로**: 순서를 정해 순차 진행하되 앞선 선택을 관찰
  에서 숨기면 동시 결정과 등가다. 이 은닉이 실제로 지켜지는지 C3 probe("진행 중인
  상대 선택 변조 → 내 관찰 불변")로 검증하라.
- **인터럽트/반응 결정**: 상대 턴 중 발동하는 선택은 `currentDecision`이 반응자를
  반환하는 것으로 모델링한다 — 계약이 그대로 수용한다.

## 6. 은닉·다인수 게임(훌라류) 특별 규칙

- **hiddenInfoProbe는 "상대 손패+스톡 재분배"가 표준형**: viewer 자신의 정보와 공개
  정보는 절대 건드리지 않는다.
- **3~4인 좌석 계획**: `seatingPlan`은 candidate(순열 index 0)가 모든 좌석에 앉는
  회전 순열이 최소 요건 (4인이면 4개).
- **팀 게임**: `spec.teams`를 선언하면 페어드 통계가 팀 단위(팀 승리·팀 점수차)로
  계산된다. 선언 없이 팀 게임을 돌리면 공동 승자 처리로 승률이 0.5로 뭉개진다.
- **점수 구조**: 남은 패 벌점제라면 composite score 부호에 주의 (높을수록 좋게 변환).

## 7. 게임 계열별 추가 규칙 (3차 갭 분석 반영)

- **승/패 전용 게임 (마진 없음 — 오목·아발론·레이스류)**: scoreDiff는 승패의 재표현일
  뿐 정보가 없다. 웨이브 기준을 `criteria.minScoreDiff = 0`으로 설정하고 scoreDiff
  열은 무시하라. 이 설정 없이 기본 기준을 쓰면 모든 후보가 near-miss로 오판된다.
- **숨은 진영 게임 (아발론·마피아류)**: `spec.teams`는 **고정·공개 팀 전용**이다.
  진영이 은닉이면 teams를 선언하지 말고 `Outcome.winners`에 승리 진영 전원을 담아라
  — 승률 계산은 winners 기반으로 올바르게 동작한다. scoreDelta는 진영 풀링이
  불가능하므로 승/패 전용 게임 규칙(위)을 함께 적용하라. 역할 배정은 시드→상태
  경로로 두면 좌석 미러링이 역할도 함께 순회한다.
- **비대칭 진영/로드아웃 (Root·덱·세력 선택)**: 비대칭 요소는 **좌석에 결합**하라 —
  그러면 좌석 미러링이 비대칭도 상쇄한다. 기본은 미러 설정(모두 같은 진영/덱)으로
  실력만 측정하고, 비대칭 자체의 평가는 설정별 어댑터로 분리한다. (§5.7 덱 규칙의
  일반형.)
- **동시 행동 게임 (드래프트·동시 공개)**: 은닉-순차 모델로 등가 변환하되, **후행자의
  합법수가 선행자의 선택에 의존하지 않도록** 합법수를 "동시 시점 기준"으로 생성해야
  등가가 성립한다. 은닉은 C3 probe로 검증하라.
- **협상·거래 게임 (카탄류)**: 오퍼는 자유형이 아니라 **이산화된 템플릿**(자원 조합의
  유한 집합)으로 결정 지점화하라. encodeChoice가 안정적이어야 하고, 오퍼 공간이 크면
  C4(decisions/sec)가 먼저 압박을 알려준다.
- **기억 의존 게임 (카운팅류)**: 봇 인스턴스는 **게임 내에서는 상태(카운팅 메모리)를
  가져도 되지만, 게임 간 캐리오버는 금지**다(러너가 매 게임 fresh 인스턴스를 만들며,
  이를 우회하는 모듈 전역 상태는 결정론 위반). 가능하면 관찰에 공개 히스토리를 포함해
  봇 메모리 없이도 정보 집합이 완전하게 하라 — 봇 구현과 재현 디버깅 모두 쉬워진다.
- **초장기 게임 (수백 결정·저처리량)**: C4 blocker는 "이 게임 그대로는 수십만 판
  루프가 물리적으로 불가"라는 정직한 판정이다. 축소 설정 어댑터(작은 맵·낮은 목표
  점수), 서브게임 단위 평가(한 라운드=한 게임)로 우회하라.
- **다인 자유전의 킹메이킹**: 후보 1 + 동일 기준선 N-1 구성은 하나의 생태계 표본이다
  — 채택 결론이 다른 상대 구성에서 뒤집힐 수 있음을 INTERPRETATION §"FFA 해석 경고"와
  함께 읽어라. 필드 믹스 웨이브는 로드맵.
