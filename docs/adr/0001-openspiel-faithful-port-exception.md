# ADR-0001 — OpenSpiel 알고리즘 충실 이식 라이선스 예외

**상태**: 채택됨 (2026-07-23)

## 맥락

`DESIGN.md` 기본 정책은 "코드 복사 없음, 아이디어 수준 체리픽 + 자체 구현"이다.
그런데 MCTS(UCT)·IS-MCTS·MCCFR 같은 탐색/학습 알고리즘은 미묘한 디테일(타이
브레이크 규칙, 확장 순서, importance-sampling 보정 등)이 정확성에 직결되고,
"아이디어만 체리픽해 자체 재발명"하면 검증되지 않은 미묘한 버그가 들어갈
위험이 크다. OpenSpiel(DeepMind, Apache-2.0)은 이 정확한 알고리즘의 레퍼런스
구현을 이미 갖고 있다.

## 결정

OpenSpiel의 **알고리즘 구현**(`python/algorithms/`의 MCTS·MCCFR)에 한해
로직을 기준 삼은 **충실 이식(faithful port)**을 허용한다 — 파생 사실과 원
출처를 해당 파일 상단 주석과 `docs/CREDITS.md`에 명시한다는 조건으로. 게임
콘텐츠(카드·규칙 등)의 "코드 복사 없음" 정책은 그대로 유지한다 — 이 예외는
순수 알고리즘 모듈에만 적용된다.

## 대안

- **아이디어만 체리픽해 자체 재구현**(기존 정책 그대로): 기각 — P5에서 실제로
  겪은 사고(타이브레이크가 보상을 무시하는 이식 결함)가, 정확히 이런 종류의
  "대충 재구현"에서 나온다는 것을 실증했다.
- **npm 패키지로 기존 MCTS 라이브러리 설치**: 기각 — Loop Forge의 게임 중립
  `GameAdapter` 계약에 맞게 커스터마이즈(rolloutFactory, tacticalDepth,
  rootOverride 등 훅)해야 해서 외부 라이브러리로는 불가능.

## 결과

`search/mcts.ts`·`search/ismcts.ts`·`learn/mccfr.ts` 3개 모듈이 이 예외로
구현됐다. 이식 충실도 결함(P5)을 실제로 발견·수정한 사례가 있어(GAP-ANALYSIS-8
§2), "이식이니까 정확할 것"이라는 가정도 검증 없이는 안전하지 않다는 교훈이
남았다 — 이식 후에도 단위 테스트로 원 구현의 불변식(예: 타이브레이크 규칙)을
직접 고정해야 한다.
