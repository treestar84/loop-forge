# ADR-0004 — 점수차 임계를 고정 상수 대신 캘리브레이션에서 파생

**상태**: 채택됨 (2026-07-24~25)

## 맥락

`DEFAULT_CRITERIA.minScoreDiff = 5`가 전 게임에 공통 상수로 쓰였는데, 점수
단위·스케일은 게임마다 완전히 다르다(오목은 승/패뿐, 하스스톤은 체력 0-30,
스플랜더는 승점 소수 단위). 실측 결과 스플랜더·도미니언·윙스팬 3게임 전부
"승률은 압도적(0.90~1.00)인데 평균 점수차가 5를 못 넘어" holdout 직전에
탈락하는 동일 패턴이 반복됐다(GAP-ANALYSIS-8 §1.5).

## 결정

`loop/calibrate.ts`의 `measureNoiseFloor`가 `scoreDiffStdDev`(항등 자기대국의
점수차 표준편차)를 함께 계산하고, `kernel/blueprint.ts`의 `deriveBlueprint`가
`recommendedMinScoreDiff`를 이 값의 **2σ**로 파생한다(승/패 전용 게임은 0,
캘리브레이션 미제공 시 기존 상수 5로 폴백 — 하위호환). "노이즈와 구별 가능한
마진"이라는 게 게이트의 진짜 목적이지, 임의 크기의 마진 요구가 아니다.

## 대안

- **게임별로 손으로 상수를 다시 튜닝**: 기각 — 매 게임마다 사람이 판단해야
  해서 "새 게임 자동 대응"이라는 프로젝트 목표에 정면으로 위배.
  M1(`hiddenTeamStructure`)·M2(`cooperativeStructure`)와 같은 패턴(옵트인 +
  실측 기반 자기참조)으로 통일한 것.

## 결과

교정 직후 재도전한 3게임 중 스플랜더·도미니언은 파생 임계로 holdout까지
통과했으나 **regression 게이트(ADR-0003)에서 챔피언 열세로 정확히 차단**되고,
윙스팬은 전 티어 통과해 채택됐다 — P6과 O10 두 결정이 서로 다른 실패 모드를
정확히 잡아내는 것이 동시에 실측 확인됐다(어느 하나만 있었으면 오채택 또는
오탈락이 발생했을 상황).
