# ADR-0012 — 앵커 래더와 홀드아웃 상대 분리

- 상태: 채택됨 (2026-07-29, GAP-ANALYSIS-11 D3)
- 관련: ADR-0010(Opus봇 1회 설계 후 고정), ADR-0009(억지 반복 금지)

## 맥락

루프의 모든 게이트 상대는 내부 봇(heuristic/챔피언)뿐이라 "외부 강자를
이긴다"가 최적화 신호에 없었다(GAP-11 R1). 외부 계측을 넣더라도 상대가
고수 1명이면 두 병리가 남는다: ① 오목 진단이 카드 1~5 전부 0%였듯 손실
함수가 무정보(그래디언트 소실), ② 그 봇의 버릇 공략(과적합)을 실력 향상과
구별할 수 없음.

## 결정

게임별 **앵커 래더**를 등록·봉인한다:

| 등급 | 정의 | 용도 |
|---|---|---|
| L1 중수 | heuristic < L1 < L2를 등록 전 실측으로 확인한 봇 | 그래디언트 복원 |
| L2 고수 | 기존 Opus 즉흥설계봇(ADR-0010으로 이미 고정 소스) | 피드백 루프의 주 손실 함수 |
| L3 고수2 | L2와 다른 전략 철학으로 별도 설계, 피드백 경로 **코드 수준 차단** | 초월 판정 전용 홀드아웃 |

구현: `BenchmarkAnchor.kind`에 `'external'`, `role: 'feedback' | 'holdout'`
추가. 홀드아웃 앵커는 (a) `runWave`의 challenge 계측에 넣으면 throw,
(b) trajectory/probe 저장 시 `sourceAnchor`로 전달되면 throw — 설계 피드백
경로(LossReport·프로브 은행·설계 브리프)에 홀드아웃 데이터가 유입될 수 없다.
challenge 계측은 **채택 판정에 불개입**(계측 열일 뿐 게이트가 아님).

이것은 시드 원장의 holdout 뱅크 규칙("평가에 쓰는 시드와 학습에 노출되는
시드를 분리")을 **상대(opponent) 축에 대칭 적용**한 것이다.

## 대안

- **단일 외부 앵커**(GAP-11 v1 초안): 과적합 검출 불가 + 0% 무정보 문제
  미해결로 기각.
- **PSRO/리그식 population 학습**(AlphaStar): 상대 풀을 온라인으로 계속
  생성 — 이 예산(단일 맥북, 무거운 연산 동시 1개)에서 비용 불가하고, 고정
  래더 + 홀드아웃 분리로 같은 목적(다양화·과적합 검출)의 최소본을 얻는다.
- **challenge를 채택 게이트로 사용**: 특정 외부 봇에 과적합한 채택을
  만들고 comparabilityKey 문맥을 오염시켜 기각 — 채택은 기존 다단 게이트
  그대로, challenge는 큰루프의 손실 함수로만 쓴다.

## 결과

- 초월 판정 기준이 명확해짐: L3 홀드아웃 상대 승률 CI 하한 > 0.5.
  L2만 이기고 L3에 지면 "과적합"이 실측으로 드러난다.
- 리스크: L1이 너무 약하면 그래디언트 복원 실패, L3가 L2와 같은 스타일이면
  홀드아웃 무의미 — 등록 전 실측 게이트(L1: heuristic<L1<L2 확인, L3: L2와
  행동 지문 거리 확인)로 완화. 등록 후에는 기존 앵커 봉인 규칙(재등록
  throw)이 그대로 적용된다.
